# Security Policy & Binary Verification

## 1. Reporting a Vulnerability

If you discover a security issue (path traversal, command injection, archive extraction bug, TLS verification issue, etc.) in Basalt:

- Please open a private security advisory via **GitHub Security Advisories** (`https://github.com/Markesrrr/Basalt/security/advisories/new`) when available, or file a concise report on [GitHub Issues](https://github.com/Markesrrr/Basalt/issues) without publishing weaponized exploit payloads.

## 2. Cryptographic Verification of Downloads

Basalt verifies downloaded artifacts on disk before execution:

- **Mojang Client JARs, Libraries & Assets:** FIPS 180-4 **SHA-1** verification against official Mojang manifests.
- **Eclipse Temurin 21 JDK:** **SHA-256** verification before unpacking.
- **Modrinth v2 Files:** **SHA-512** / **SHA-1** verification against Modrinth API file hashes prior to writing `.jar` / `.zip` files into your library folders.
- **Release Binaries (`basalt.exe` / `.zip`):** Every GitHub Release includes `SHA256SUMS.txt` generated by the automated GitHub Actions build pipeline (`windows-latest`). Verify locally in PowerShell before running:

```powershell
Get-FileHash .\basalt.exe -Algorithm SHA256
Get-FileHash .\basalt-v0.3.0-windows-x64.zip -Algorithm SHA256
```

## 3. Windows SmartScreen & Unsigned Open-Source Builds

Pre-release open-source binaries (`basalt.exe`) built by GitHub Actions are **not** signed with a paid commercial Authenticode EV code-signing certificate yet. Because of this, **Windows Defender SmartScreen** may show *"Windows protected your PC"* on newly published releases until the build builds reputation or is verified manually:

1. Download only from the official repository: `https://github.com/Markesrrr/Basalt/releases`.
2. Compare your file's SHA-256 hash against `SHA256SUMS.txt` on the release page.
3. Alternatively, extract `basalt-v0.3.0-windows-x64.zip` or review the source code and build directly with `cargo build --release --workspace`.
